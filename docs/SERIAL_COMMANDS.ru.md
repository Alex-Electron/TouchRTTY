# Управление TouchRTTY по USB serial

> 🇬🇧 [Read in English](SERIAL_COMMANDS.md)

После прошивки Pico показывается как USB CDC ACM — `COM<N>` на
Windows, `/dev/ttyACM0` на Linux, `/dev/tty.usbmodem*` на macOS.
Открываешь на **115200 8N1**, шлёшь `VERSION`, должно ответить
примерно так:

```
>> TouchRTTY Phase9 B265 (built May 12 2026 05:42:11)
```

Ответило — significa serial-путь жив, дальше делаем что угодно. Если
молчит — проверь, что порт правильный и что его не держит другая
программа (PuTTY, терминал PyCharm, Arduino IDE).

Команда — одна строка. Pico принимает и `\r\n`, и голый `\n` как
конец строки. Ещё есть idle-таймаут 500 мс — если ты набрал и
остановился, коробка через полсекунды выполнит команду сама.
Удобно, если общается с тобой скрипт, который не шлёт перевод строки
явно.

Если набрать `HELP` на самой коробке — получишь краткий summary.
Этот документ — длинная версия с примерами и мелкими сюрпризами,
которые из help-экрана не очевидны.

## Настройка DSP

Эти четыре числа — сердце петли. Изменения вступают на следующем
сэмпле, декодер не перезапускается. Если нашёл sweet spot — `SAVE`
запишет в flash, и они переживут перезагрузку.

| Команда | Диапазон | Default | Что делает |
|---|---|---|---|
| `ALPHA <0.005..0.200>` | float | 0.05 | Полоса петли DPLL. Выше = ловит быстро, дёргается сильнее. Ниже = чистый timing, но медленно цепляется за новый сигнал. |
| `BW <0.3..2.0>` | float | 1.0 | Коэффициент `K` для LPF. Шире = пропускает больше offset'а по частоте; уже = режет шум, но придирается к точной частоте. |
| `SQ <dB>` | float | 6.0 | Порог сквелча. Ниже этого SNR выход молчит. Подними, если из чистого шума летит шторм `[ERR]`. |
| `FREQ <Hz>` | float | 1500 | Центральная аудио-частота, на которой декодер слушает. Если AFC включена, это просто стартовый намёк. |

```
> ALPHA 0.07
>> ALPHA=0.0700

> BW 1.4
>> BW=1.40

> FREQ 2210
>> FREQ=2210.0
```

`BW` и `K` — алиасы для одного и того же параметра, на случай если в
старых документах встретишь любое из двух названий.

## Говорим, какой именно RTTY ждём

Надо выставить baud, shift, stop bits и polarity. Дефолты — любительский
RTTY (45.45 / 170 / 1.5 / NOR), нормально работает на ham-диапазонах,
но коммерческие станции не возьмёт.

| Команда | Что выбираешь |
|---|---|
| `BAUD 0` / `BAUD 1` / `BAUD 2` / `BAUD 3` | 45.45 / 50 / 75 / 100 baud |
| `BAUD AUTO` (или `BAUD 4`) | Пусть сам определит |
| `SHIFT 0..7` | 85 / 170 / 200 / 340 / 425 / 450 / 500 / 850 Гц spacing |
| `SHIFT AUTO` (или `SHIFT 8`) | Авто-детект shift |
| `STOP 0..2` | 1.0 / 1.5 / 2.0 stop bits |
| `STOP AUTO` (или `STOP 3`) | Авто-детект по статистике межфреймовых gap'ов |
| `INV NOR` / `INV INV` | Полярность. NOR = Mark — верхний тон. Стандарт для любительства. |
| `INV AUTO` | Флипнет, если ошибки держатся высокими ~0.8 сек |

Авто-режимы хорошие — `AUTO` для всего работает в большинстве случаев.
Лочить руками имеет смысл, если ты точно знаешь, что слушаешь, и
хочешь сэкономить время на детекте.

Полярность — то, на чём чаще всего обжигаются. Если строишь WebSDR в
USB, а станция реально передаёт в LSB (DWD так делает), Mark и Space
меняются — увидишь мусор. Тапни `INV` один раз. Всё.

**Полезные комбинации, которые я держу под рукой:**

| Сигнал | Настройки |
|---|---|
| Любительский RTTY, любой диапазон | `BAUD 0` `SHIFT 1` `INV NOR` |
| DWD weather (4582 / 10100.8 кГц, строй USB) | `BAUD 1` `SHIFT 5` `INV NOR` |
| Российские коммерческие / Славянка | `BAUD 1` `SHIFT 1` `INV INV` часто |
| SITOR-B / NAVTEX | `BAUD 2` `SHIFT 1` |

## Тоглы вкл/выкл

Быстрые переключатели. Каждый отвечает тем, что только что сделал.

* `AFC ON` / `AFC OFF` — автотрекинг частоты. Уход ±100 Гц от
  настроенной `FREQ`. У меня всегда ON.
* `AGC ON` / `AGC OFF` — авто-усиление. Выключи, если хочешь, чтобы
  абсолютные амплитуды для SNR-метра значили что-то физическое.
* `SCALE EXP` / `SCALE LIN` — палитра водопада. `EXP` вытягивает
  слабые сигналы из шума, всё выглядит живее, но чуть «шумнее».
* `WIDTH <30..120>` — символов в строке на экране. Подстраивай под
  размер шрифта.
* `SEARCH` — форсирует FFT-скан 300–3000 Гц, выбирает самый сильный
  RTTY-похожий несущей, ставит FREQ и включает AFC. То же самое, что
  кнопка SEARCH в нижнем баре.

## Выбираем decoder path

Внутри две параллельных цепочки демодуляции: узкий фильтр (path A,
хорош на чистом слабом сигнале) и широкий (path B, хорош на фейдинге
или непонятном shift). Можно гонять любую отдельно или сливать вместе.

* `PATH A` — только узкая цепочка
* `PATH B` — только широкая
* `PATH HYB` (или `PATH LLR`) — LLR-fusion обоих. Это дефолт, и почти
  всегда правильный ответ.
* `DYN ON` / `DYN OFF` — как HYB взвешивает цепочки. ON = по
  per-chain SNR. OFF = чистое геометрическое среднее. Default ON, но
  OFF может быть надёжнее, если одна из цепочек плохо оценивает свой
  SNR.
* `WEIGHTS <wa> <wb>` — ручные веса, если хочешь форсировать
  соотношение. Внутри нормализуется к сумме 1, так что `WEIGHTS 7 3`
  равно `WEIGHTS 0.7 0.3`.

Случая, когда чистый PATH B бьёт HYB, я не находил. Path A иногда
выигрывает на очень чистом слабом любительстве. В основном HYB.

## Нейросетевой классификатор

Начиная с B261 есть маленький (~44 КБ) MLP, который голосует на
неоднозначных Baudot-фреймах. Две команды:

* `NN ON` — задействовать классификатор
* `NN OFF` — чистое решение по знаку, без NN

Ключевая деталь: даже с `NN ON` сеть стреляет только когда вход
реально неопределённый — конкретно когда абсолютное значение слабого
data-бита ниже 30 % от оценённого уровня сигнала (B264 confidence
gate). Если биты чёткие, hard decision уже правильная, и NN сама
себя пропускает. Это и есть то, что не даёт NN сделать *хуже* на
чистом сигнале — раньше интеграция была без гейта, и получалась
противная U-образная кривая. Историю расскажет
[NN_TRAINING.ru.md](NN_TRAINING.ru.md).

Production-веса — **v13** (PyTorch, рецепт `weight_uncertain=3.0`).
Если хочешь свои — там пошаговый walkthrough.

## Фильтрация и валидация фреймов

* `NOTCH ON` / `NOTCH OFF` — LMS adaptive notch chain. Убивает узкие
  несущие / гетеродины внутри audio-passband. Стоит включать, когда
  где-то рядом BFO-leak или другая станция.
* `VIT ON` / `VIT OFF` — soft-Viterbi frame gate. ON = строго (полная
  валидация по энергии + start/stop). OFF = только по stop-биту
  (либеральнее, пропускает больше текста, но и больше ошибок).
* `NR ON` / `NR OFF` — Wiener spectral noise reduction.
  Экспериментальная. Три прогона подряд не показали измеримого
  выигрыша, дефолт OFF. Тогл оставили на случай тестов на странном
  шуме.

## Сохранение и инспекция

* `SAVE` — записать все текущие настройки в settings-страницу flash.
  Восстановятся на следующем boot. Калибровка тача тоже.
* `CLEAR` — сбросить DSP-интеграторы (gain AGC, фаза DPLL, история
  ошибок). Настройки не трогает, только runtime-state. Полезно, если
  AGC залип на максимуме и не отпускает.
* `STATUS` — дамп всего. Это твой друг при отладке:

```
> STATUS

=== STATUS (B265) ===
ALPHA=0.0500 BW=1.00 SQ=6.0
BAUD=50 SHIFT=5(450) INV=NOR AFC=ON
FREQ=2210.0 SNR=14.2 SIG=-12.3 AGC=1.50
STOP=1.5(1.5) SQ=OPEN ERR=3% DIAG=OFF
STOP-DET: gap_last=1.48T hist[1.0/1.5/2.0]=2/85/13
NN=ON NOTCH=OFF VIT=ON
====================
```

* `VERSION` (алиасы `VER`, `ID`) — build number прошивки и timestamp
  компиляции C++. Пригодится в баг-репорте.

## Diagnostic streams

Для глубокой отладки:

* `DIAG ON` / `DIAG OFF` — включает периодическую (~500 мс) сжатую
  диагностическую строку. Полезно, чтобы видеть SNR и AGC в
  реальном времени, не глядя на экран.
* `DUMP SPEC` — one-shot дамп текущих 512-бин FFT-магнитуд. Полезно
  для offline спектрального анализа.
* `DUMP MS` — one-shot дамп 480 сэмплов огибающих Mark и Space.
  Полезно для инспекции вывода демодулятора.

### `DUMP FRAMES` — capture training data

Это добавка B265, которая позволяет бутстрапить NN-тренировку с
реальных записей.

```
> DUMP FRAMES ON
>> DUMP FRAMES ON
```

После этого каждый принятый декодером Baudot-фрейм даёт одну строку:

```
FR -35.50 184.20 -176.40 -188.10 192.30 156.70 -178.80 175.10 16
   ^      ^----------- 5 data bits ----------- ^      ^   ^
   start                                       stop   sig hard_char
```

Значения не нормализованы. Поделить всё, кроме `sig` и `hard_char`,
на `sig` — получишь биполярное ±1 представление, которое ждёт NN.
`hard_char` (0–31) — это чистое решение по знаку *до* любого
NN-override, и оно работает как label для тренировочных данных,
когда ты уверен, что декодер тут прав.

Выключить — `DUMP FRAMES OFF`. Парный тул
[`tools/parse_dump_frames.py`](../tools/parse_dump_frames.py) читает
serial-лог и пишет numpy `.npz` для тренера.

## Быстрые рецепты

### Настроиться на DWD на 10100.8 кГц USB

```
BAUD 1
SHIFT 5
INV NOR
FREQ 1700      # зависит от audio-mapping WebSDR, подстрой
AFC ON
PATH HYB
NN ON
```

### A/B-тест NN на одинаковом аудио

```
NN OFF
# проиграй тестовый WAV через audio loopback, логируй serial
NN ON
# проиграй тот же WAV ещё раз, лог снова
# diff'ни два лога / прогони cer_analyze на обоих
```

### Capture training data с известно-хорошей записи

```
NN OFF              # нужны hard-decision labels
DUMP FRAMES ON
# проиграй запись, сохраняй serial в файл
DUMP FRAMES OFF
```

Дальше log через `parse_dump_frames.py` → npz → скармливаешь
`train_nn_torch.py --real-npz ...`.

## Когда что-то не совпало

Всё, что не распознано:

```
>> UNKNOWN: <что ты ввёл> (try HELP)
```

Я иногда использую это как дешёвый ping — если `PING` возвращается
как `>> UNKNOWN: PING`, значит serial-путь жив.

Если послал валидную команду и тишина — проверь:
1. Перевод строки долетел? Некоторые terminal'ы шлют только `\r`.
2. Порт не держит другой процесс?
3. Pico не упал? `VERSION` должен отвечать всегда. Если нет —
   power-cycle.
