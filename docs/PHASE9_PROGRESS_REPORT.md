## 1. Honest read — что это означает

Соль в том, что Этапы 1-2 — это **подготовительные**. План обещал +3-5 дБ от них, на деле получили ~0 дБ по threshold. Это не провал, это **ожидаемая картина**:

- **Soft-LLR + Soft-Viterbi** (B242+B243) дают *честный* framer: раньше декодер на −8 дБ выдавал ложняк (6% CER), теперь молчит или отдаёт чистое. Threshold не сдвинулся, потому что proc ≥5% это CER, а не "дал фрейм". Framer улучшается, но ADC/IQ остались теми же.
- **LMS-notch + BPF** (B244+B245) нужны **не для AWGN**. Они делают сигнал устойчивее к QRM/помехам, которых в AWGN-тесте нет. AWGN-нейтральность — правильный результат.

Настоящий порог вниз толкают:
- **Stage 3 (fusion)**: вторая ветка IQ даёт другой trade-off ISI/SNR. Weighted combine выберет лучшее на каждой позиции символа. +0.5-1.5 дБ.
- **Stage 4 (spectral NR)**: FFT-based noise subtraction. +1-2 дБ.
- **Stage 5 (ML post)**: маленькая CNN по eye-diagram. +1-2 дБ.

Суммарный потенциал Этапов 3-5: **+3-5 дБ** → threshold **−13..−15 дБ**. Это цель.

## 2. Детальный разбор — что каждый этап реально сделал

### B242 — Soft-LLR bit decision

**Идея**: вместо hard-slice (знак `integrate_acc`) — хранить soft-значение и валидировать границы фрейма адаптивным порогом.

**Код**: `STOP_MIN_FRAC` / `START_MIN_FRAC`, нормализация к EMA сигнала (`sig_level`).

**Что дало**:
- На **+20..−6 дБ**: те же 0-2% (ничего не потерял)
- На **−8 дБ**: ложных фреймов стало БОЛЬШЕ (0% → 6%) — soft-LLR принял слабые фреймы, в которых знак был случаен, → неправильные Baudot-коды прошли как "valid"
- На **−14 дБ**: декодер **ожил** (0 символов → 282). Пограничный SNR, на котором soft-LLR распознаёт фрейм там, где hard-slice отбрасывал

**Вывод**: Stage 1.1 сам по себе ничего не выигрывает, но открывает дорогу Stage 1.2 — теперь есть soft-метрики, которые можно использовать для фильтрации мусора.

### B243 — Soft-Viterbi framer

**Идея**: к soft-валидации границ добавить soft-валидацию **data-битов**. Два гейта:
- `weakest_link`: отклонить если `min(|soft_data[i]|) < 0.10·sig_level` — слабейший из 5 битов должен быть уверенным
- `frame_avg`: отклонить если `mean(|soft_start| + |data[0..4]| + |stop|) / 7 < 0.15·sig_level` — общая статистика фрейма

Первая попытка (пороги 0.20/0.30) дала **регрессию**: чистые фреймы на +20 дБ резались (4.94% CER). Ослабил до 0.10/0.15 — baseline восстановился.

**Что дало**:
- **−8 дБ**: 6% → 0.00% ✓ — ложные фреймы B242 вычищены
- **−10..−14 дБ**: качество осталось похожим на B242 (weakest-link на таких SNR часто режет и валидные фреймы)

**Вывод**: Stage 1.2 очистил **край порога**. Threshold по CER=5% остался −10 дБ, но бин −10 перестал ловить случайные байты. Это **необходимое условие** для последующих этапов: без честного framer любые DSP-улучшения ловили бы артефакты, а не реальный сигнал.

### B244 — LMS-notch adaptive

**Идея**: 2-order Nehorai-style constrained adaptive notch, два экземпляра в каскаде — один сканирует полосу 300-1350 Гц (ниже RTTY), второй 1650-3200 Гц (выше RTTY). LMS-градиент `dy/da ≈ x1 − r·y1` тянет `a` к координате доминирующего тона в полосе; constraint держит null вне RTTY-диапазона.

**Код**: `src/dsp/lms_notch.hpp`. Pole radius r=0.985 → BW ≈ 48 Гц. μ=5e-6.

**Что дало**:
- **AWGN-only**: threshold −10 дБ **сохранён**, нейтрально. Это правильно — в AWGN нет узкополосной компоненты, которую нужно нулить; notch слегка дрейфует, но не вредит.
- **CW QRM**: threshold −10 дБ, CER ≤ 2% от +20 до −8 дБ. Без notch CW обычно разваливает декодер даже на +10 дБ (сбивает AGC и IQ). Субъективно +1-2 дБ.

**Оговорка**: уровень CW в тесте не зафиксирован — нужно повторить со злой помехой (например 0 дБ относительно сигнала), чтобы подтвердить robustness.

### B245 — Input BPF 300-3000 Hz

**Идея**: Butterworth HPF@300 + LPF@3000 после AGC, перед LMS-notch. Дополняет существующий 63-tap FIR bandpass — срезает DC/hum <300 Гц и HF-шум >3 кГц.

**Код**: `design_hpf()` в `src/dsp/biquad.hpp`, два биквада в `dsp_pipeline.cpp`.

**Что дало**:
- Threshold −10 дБ **сохранён**
- Bin −10 дБ стал **0.00%** (у B243.1 был ~15% из-за merged bin)
- Чистый вход в LMS-notch и IQ-демод — готов к fusion (Stage 3)

**Вывод**: AWGN-нейтрально, как и должно быть для фиксированного BPF без QRM. Главный смысл — гигиена пайплайна для следующих этапов.

## 3. Методологические заметки

### 3.1 Sync-маркеры

B241 ввёл маркеры `=NN=` в RTTY-поток — по одному на каждую точку SNR. `cer_analyze.py --markers` режет decoded-поток по ним. Это дало воспроизводимые бины на SNR.

**Проблема**: иногда маркер теряется (например, когда LMS-notch на cold-start мангает первые символы). Тогда бин `N` захватывает содержимое бина `N+1`, CER вырастает искусственно. В B245 потерян маркер =18=, бин −12 захватил −14, потому 31%.

**Mitigation**: держать cold-start notch <1 сек, маркеры дублировать (пока не делал, заметка).

### 3.2 CER-метрика и шум

`cer_analyze.py` = Levenshtein к циклическому GT. Оптимизирован в B244 (O(49·N²) → O(49·N + 3·N²)).

Иногда показывает "фантомные" проценты на высоких SNR (7-8%) из-за одиночных байт-лосс в serial или остатков предыдущего decoded-потока. **Реальный threshold читается по сплошному 0% диапазону**, не по точечным выбросам.

### 3.3 AWGN vs реальный эфир

Все замеры через `rtty_simulator.html` → аудио-линия → ADC. Это синтетический AWGN. **Реальный эфир** добавит:
- Selective fading (частотный fading на разных shift-тонах)
- Импульсные помехи
- Дрейф частоты TX
- QSB (slow fade)

Stage 4-5 (spectral NR + ML) в синтетике могут дать меньше, чем в реальном эфире, и наоборот. Нужен **реальный датасет** (задача #16) до Stage 5.

## 4. Что дальше

### Stage 3 — Fusion двух IQ-веток

План:
- **Path A** (уже есть): biquad LPF с BW ≈ baud
- **Path B** (новое): raised-cosine FIR с BW ≈ 1.5·baud, matched filter
- **Fusion**: weighted sum огибающих, вес = f(SNR_estimate)

Мелкие шаги:
1. **3.1** — добавить вторую IQ-ветку с raised-cosine FIR (без fusion, просто параллельно, для замера)
2. **3.2** — fusion-логика weighted combine
3. **3.3** — оценка SNR для dynamic weights
4. **3.4** — A/B сравнение с baseline

Каждый шаг — отдельный билд, коммит, замер.
